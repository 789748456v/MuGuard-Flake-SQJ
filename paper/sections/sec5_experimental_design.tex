\section{Experimental Design}
\label{sec:design}

We structure our empirical investigation around four research questions progressing from erosion prevalence and baseline blind spots to fail-closed repair and CI deployment:
\begin{itemize}[nosep]
    \item \textbf{RQ1 (Prevalence, SOTA Adaptations, and PR Boundaries):} How pervasive is silent oracle erosion across historical artifacts, same-model SOTA adaptations, and modern LLMs, and what false-rejection boundaries emerge on developer pull requests?
    \item \textbf{RQ2 (Mechanisms and Multi-Paradigm Blind Spots):} Which edit mechanisms drive erosion, and why do static structural rules, dynamic coverage gates, and diff-only or focal-aware cross-vendor LLM judges fail to block them?
    \item \textbf{RQ3 (Fail-Closed Gating, Cost Break-Even, and Witnesses):} How does \textsc{MuGuard-Flake} balance soundness, unseen fault loss, held-out yield, and expected CI cost against static, coverage, and LLM-judge gates, and what do witnesses add over scalar counts or misleading hints?
    \item \textbf{RQ4 (Latency, Abstentions, and Subset Gating):} What uncached probing times, abstention causes, and offline or online subset-sampling trade-offs govern practical CI deployment?
\end{itemize}

\subsection{Benchmark Cohort, Model Snapshots, and Confirmatory Separation}

We draw an initial cohort of $\BenchInitAttempted$ flaky tests across 70 repositories from two public benchmarks: Java ID and OD-victim tests from \textsc{FlakyDoctor}'s \textsc{IDoFT} suite~\cite{chen2024flakydoctor}, and Python OD-victim and OD-brittle tests from \textsc{iPFlakies}~\cite{wang2022ipflakies}. All builds execute inside hermetic Docker containers under 120\,s timeouts using OpenJDK, Maven, \textsc{NonDex}, and PIT for Java, and isolated virtual environments with pytest and coverage.py for Python. Cohort construction enforced baseline single-probe ceilings of 90\,s in Java and 45\,s in Python.

Applying strict node- and phase-attributed filtering reduced the cohort from $\BenchInitAttempted$ attempted tests to $N = \BenchEligible$ eligible tests across $\BenchProjects$ repositories (Table~\ref{tab:benchmark}). Five tests fell below our three-obligation eligibility floor: four during initial baseline freezing and one after attribution auditing excluded seven inherited JUnit~5 superclass kills. To prevent survivorship bias, we never replace excluded tests. Instead, we report primary metrics on all $\BenchEligible$ eligible tests alongside intent-to-treat (ITT) rates across all $\BenchInitAttempted$ attempted tests.

To prevent harness and guard rules from overfitting to evaluation models, we assign five LLMs from four vendors to three distinct roles. DeepSeek Flash and DeepSeek V4 Pro served as \emph{exploratory} multi-round backbones during static-guard design. Alibaba Qwen 3.7 Plus acts as our pre-specified \emph{confirmatory} multi-round backbone, and single-pass runs on Moonshot Kimi K2.5 and Zhipu GLM-5 test cross-family generalization.

All five models were invoked via official vendor APIs with exact snapshot identifiers and prompt--response caches archived in our replication package. Standard calls used greedy decoding at temperature 0.0 under 8k--16k initial token caps, handling rare DeepSeek reasoning-token overflows via the vendor's bounded-reasoning fallback without altering any prompt. Before confirmatory runs, we locked attribution, bytecode restoration, lifecycle hooks, and guard rules behind an automated regression suite.

\subsection{Historical Artifacts, SOTA Adaptations, Repair Baselines, and Blinded Audit}

\paragraph{Historical Artifacts, Same-Model SOTA Adaptations, and Pull Requests.}
Beyond our controlled gating grid, we evaluate three external repair sources: verbatim historical patches, same-model agent adaptations, and developer pull requests. First, we replay official passing patches from \textsc{FlakyDoctor} (GPT-4 and Magicoder) and partner-matched \textsc{iPFlakies} rows alongside matched \textsc{MuGuard-Flake} runs. Second, to control for model vintage and language scope, we run $W^+$-standardized adaptations of \textsc{FlakyFix}~\cite{fatima2024flakyfix} at $K=1$ and $K=5$, \textsc{FlakyDoctor}~\cite{chen2024flakydoctor}, and \textsc{FlakyGuard}~\cite{li2025flakyguard}, plus a trajectory-shared \textsc{FlakyGuard}+\textsc{MuGuard} hybrid, on confirmatory Qwen 3.7 Plus (Online Resource~1, Table~S-8). \textsc{FlakyFix}-style predicts repair categories from target test code alone with out-of-benchmark exemplars, \textsc{FlakyDoctor}-style pairs neurosymbolic localization with import stitching and three-error early stopping, and \textsc{FlakyGuard}-style selects up to five baseline-executed focal functions from a pruned call graph with structured reflection. Third, we evaluate $\PRTotalInstances$ Java instances across $\PRDistinctURLs$ \textsc{IDoFT} pull requests applied atomically across each repository tree.

\paragraph{Eight Controlled Repair Gating Strategies.}
Holding localization context, partner code, stability traces, and output schema fixed at temperature 0.0 (with $K = 5$ retries on multi-round backbones and $K = 1$ on single-pass models), we compare eight gating strategies:
\begin{enumerate}[nosep]
    \item \emph{Unconstrained.} Accepts the first compiled, $W^+$-passing candidate satisfying basic non-empty, no-skip, and exception-swallowing sanity checks.
    \item \emph{Prompt Guard.} Adds explicit contract-preservation instructions prohibiting assertion deletion, projection relaxation, lossy splitting, and state clobbering.
    \item \emph{Syntactic Guard.} Enforces assertion-count preservation and blocks trivial tautologies, skip markers, and exception swallowing prior to compilation.
    \item \emph{Structural Guard.} Extends static checking with assertion-correspondence rules derived from exploratory bypasses and tested out-of-sample on Qwen 3.7 Plus, Kimi K2.5, and GLM-5. These rules flag projection downgrades, dual-call tautologies, missing focal calls, and post-action state resets.
    \item \emph{Coverage Gate.} Enforces 100\% retention of baseline focal line coverage via JaCoCo in Java and coverage.py in Python across target and edited partner scopes, returning uncovered production lines on retry. We evaluate it across all baseline-covered offline patches, pull requests, and full $K=5$ repair on confirmatory Qwen 3.7 Plus.
    \item \emph{Cross-Vendor LLM-Judge Gate.} Screens stabilized test diffs without production source slices using an independent cross-vendor model and returns natural-language erosion critiques on retry. Alibaba Qwen 3.7 Plus judges DeepSeek, Kimi, and GLM patches, while Zhipu GLM-5 judges Qwen patches across offline eroded patches, pull requests, and confirmatory repair loops. We also audit an offline focal-aware variant supplied with up to five executed focal functions (Table~S-9).
    \item \emph{Scalar Gate.} Executes the exact fail-closed $W^+ \times M_{\text{det}}$ gate of \textsc{MuGuard-Flake}, returning only the surviving count $k/M$ on erosion retries without code locations.
    \item \emph{MuGuard-Flake.} Pairs the fail-closed dual-role mutation gate with localized surviving-mutant witnesses (Algorithm~\ref{alg:muguard}).
\end{enumerate}

\paragraph{Two-Stage Blinded Ensemble Audit.}
Because mutant survival alone cannot separate benign refactoring from genuine oracle weakening, we conduct a two-stage blinded semantic audit across all $\PREvaluatedClean$ cleanly applied pull-request instances, a stratified sample of $\TaxManualN$ model-generated eroded patches, and every unique held-out $M_{\text{ext}}$-loss patch across our main gates and SOTA adaptations. In Stage~1, the first author classified unified diffs under a three-step decision tree into \emph{legitimate canonicalization} (L), \emph{test responsibility shift} (S), or \emph{genuine oracle weakening} (W).

In Stage~2, ten stateless, read-only OpenAI Codex (GPT-6-Astra) sessions independently rated the permuted items outside the repository, providing blinded cross-vendor model adjudication (Tables~S-1 and~S-7). Each session saw only complete code diffs, test-only stabilization scope, and full lost-mutant lists with production slices, blinded to strategy names, repair models, gate verdicts, merge status, and Stage-1 labels. Ten-session internal stability reaches Fleiss' $\kappa > 0.91$ with substantial Stage-1 agreement~\cite{cohen1960kappa}. On developer pull requests, we report Stage-1 primary false rejections alongside strict ensemble L-only sensitivity, with full $\kappa$ and vote-entropy diagnostics in Table~S-1.

\subsection{Prefix-Forked Witness Experiment and Clustered Statistical Inference}

\paragraph{Prefix-Forked Witness Experiment.}
To isolate whether fault localization drives recovery beyond extra retries or longer prompts, we fork every multi-round trajectory that triggers its first erosion retry before round~5. This paired pool covers all $n = \ForkTotal$ pre-round-5 triggers across $\ForkTests$ tests in $\ForkProjects$ repositories. From each identical pre-fork state, we branch into four deterministic arms. \emph{Gate-Only} abstains immediately at 0\% recovery by definition, and \emph{Scalar Ratio} returns only $k/M$. \emph{Misleading Witness} fills the exact witness template and mutant count using already-killed mutants, whereas \emph{True Witness} supplies localized surviving mutants.

\paragraph{Project-Clustered Paired Inference.}
Because flaky tests cluster within repositories, every paired comparison estimates test-weighted risk differences in percentage points with 95\% whole-repository cluster bootstrap confidence intervals over 20,000 resamples, paired with equal-repository checks and a five-point practical threshold. Project-level Rademacher sign-flip permutations test binary yields under Holm--Bonferroni control~\cite{holm1979simple} across operational soundness, fixed-cohort held-out yield, and witness recovery. For same-model SOTA adaptations, conditional harmful held-out loss (W or S) among accepted, held-out-stable, evaluable patches is tested via a two-sided null-centered studentized cluster bootstrap under four-baseline Holm adjustment (Table~S-7). Section~\ref{sec:results} presents our empirical findings.

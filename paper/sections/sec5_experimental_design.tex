\section{Experimental Design}
\label{sec:design}

We organize our cross-language study around four research questions, moving from benchmark subjects and repair gates to blinded adjudication and project-clustered inference:
\begin{itemize}[nosep]
    \item \textbf{RQ1 (Prevalence and PR Boundaries):} How pervasive is silent oracle erosion across historical tools and modern LLMs, and what false-rejection and triage boundaries emerge on developer pull requests?
    \item \textbf{RQ2 (Mechanisms and Multi-Paradigm Blind Spots):} Which edit mechanisms drive erosion, and why do static structural rules, dynamic coverage gates, and cross-vendor LLM judges fail to block them?
    \item \textbf{RQ3 (Fail-Closed Gating and Witnesses):} How does \textsc{MuGuard-Flake} balance soundness, unseen fault loss, and held-out yield against static, coverage, and LLM-judge gates, and what do witnesses add over scalar counts or misleading hints?
    \item \textbf{RQ4 (Latency, Abstentions, and Live Subsets):} What uncached probing times, Python formatting abstentions, and offline or online subset-sampling trade-offs govern practical CI deployment?
\end{itemize}

\subsection{Benchmark Cohort, Model Snapshots, and Confirmatory Separation}

We draw an initial cohort of $\BenchInitAttempted$ flaky tests across 70 repositories from two public benchmarks: Java ID and OD-victim tests from \textsc{FlakyDoctor}'s \textsc{IDoFT} suite~\cite{chen2024flakydoctor}, and Python OD-victim and OD-brittle tests from \textsc{iPFlakies}~\cite{wang2022ipflakies}. All builds execute inside hermetic Docker containers under 120\,s timeouts using OpenJDK, Maven, \textsc{NonDex}, and PIT for Java, and isolated virtual environments with pytest and coverage.py for Python. Cohort construction enforced baseline single-probe ceilings of 90\,s in Java and 45\,s in Python.

Applying strict node- and phase-attributed filtering reduced the cohort from $\BenchInitAttempted$ attempted tests to $N = \BenchEligible$ eligible tests across $\BenchProjects$ repositories (Table~\ref{tab:benchmark}). Five tests fell below our three-obligation eligibility floor: four during initial baseline freezing and one after attribution auditing excluded seven inherited JUnit~5 superclass kills. To prevent survivorship bias, we never replace excluded tests. Instead, we report primary metrics on all $\BenchEligible$ eligible tests alongside intent-to-treat (ITT) rates across all $\BenchInitAttempted$ attempted tests.

To prevent harness and guard rules from overfitting to evaluation models, we assign five LLMs from four vendors to three distinct roles. DeepSeek Flash and DeepSeek V4 Pro served as \emph{exploratory} multi-round backbones during static-guard design. Alibaba Qwen 3.7 Plus acts as our pre-specified \emph{confirmatory} multi-round backbone, and single-pass runs on Moonshot Kimi K2.5 and Zhipu GLM-5 test cross-family generalization.

All five models were invoked via official vendor APIs at temperature 0.0 and completed every eligible test across the benchmark, with exact snapshot identifiers and prompt--response caches archived in our replication package. Standard calls enforced a six-thousand-token output cap under a sixteen-thousand-token reasoning budget. On the single exploratory Flash case and fifteen Pro cases whose default high-effort reasoning trace exceeded that budget, we completed all strategies identically under DeepSeek's bounded-reasoning mode without altering any prompt. Before confirmatory runs, we locked attribution, bytecode restoration, lifecycle hooks, and guard rules behind an automated regression suite.

\subsection{Historical Artifacts, Pull Requests, Repair Baselines, and Blinded Audit}

\paragraph{Historical Artifacts and Developer Pull Requests.}
We audit official upstream passing patches verbatim: entries marked passing in \textsc{FlakyDoctor}'s GPT-4 and Magicoder logs and partner-matched rows in \textsc{iPFlakies}'s official log, excluding unlogged archive files and three partner-mismatched Python rows. Alongside verbatim auditing, we compare \textsc{MuGuard-Flake} head to head on the exact matched test subsets covered by each upstream tool. To measure false rejections on valid human fixes and subtle weakenings missed by default mutators, we evaluate $\PRTotalInstances$ Java instances across $\PRDistinctURLs$ \textsc{IDoFT} pull requests. Test-file patches are applied atomically across one repository tree, and stabilized test-only order-dependent pull requests pass through the full dual-role gate.

\paragraph{Eight Controlled Repair Gating Strategies.}
Holding localization context, partner code, stability traces, output schema, and the $K = 5$ retry budget at temperature 0.0 identical, we compare six core strategies across all models plus two dynamic and model-based gates:
\begin{enumerate}[nosep]
    \item \emph{Unconstrained.} Accepts the first compiled, $W^+$-passing candidate satisfying basic non-empty, no-skip, and exception-swallowing sanity checks.
    \item \emph{Prompt Guard.} Adds explicit contract-preservation instructions prohibiting assertion deletion, projection relaxation, lossy splitting, and state clobbering.
    \item \emph{Syntactic Guard.} Enforces assertion-count preservation and blocks trivial tautologies, skip markers, and exception swallowing prior to compilation.
    \item \emph{Structural Guard.} Extends static checking with assertion-correspondence rules derived from exploratory bypasses and tested out-of-sample on Qwen 3.7 Plus, Kimi K2.5, and GLM-5. These rules flag projection downgrades, dual-call tautologies, missing focal calls, and post-action state resets.
    \item \emph{Coverage Gate.} Enforces 100\% retention of baseline focal line and branch coverage via JaCoCo in Java and coverage.py in Python across target and edited partner scopes, returning uncovered production lines on retry. We evaluate it across all baseline-covered offline patches, pull requests, and full $K=5$ repair on confirmatory Qwen 3.7 Plus.
    \item \emph{Cross-Vendor LLM-Judge Gate.} Screens stabilized diffs with an independent cross-vendor model and returns natural-language erosion critiques on retry. Alibaba Qwen 3.7 Plus judges DeepSeek, Kimi, and GLM patches, and Zhipu GLM-5 judges Qwen patches. We evaluate this gate across all 400 offline patches, pull requests, five-model screening, and full $K=5$ repair on confirmatory Qwen 3.7 Plus.
    \item \emph{Scalar Gate.} Executes the exact fail-closed $W^+ \times M_{\text{det}}$ gate of \textsc{MuGuard-Flake}, returning only the surviving count $k/M$ on erosion retries without code locations.
    \item \emph{MuGuard-Flake.} Pairs the fail-closed dual-role mutation gate with localized surviving-mutant witnesses (Algorithm~\ref{alg:muguard}).
\end{enumerate}

\paragraph{Two-Stage Blinded Ensemble Audit.}
Semantic adjudication follows a two-stage blinded protocol across three patch sets: all 53 cleanly applied pull requests (including the 43 $W^+$-passing test-only fixes), 60 active stratified eroded patches, and all 118 unique held-out $M_{\text{ext}}$-loss patches across our evaluated gates. In Stage~1, the first author classified unified diffs under a three-step decision tree ordering legitimate canonicalization, responsibility shift, and genuine weakening.

In Stage~2, ten independent, stateless, read-only sessions of OpenAI Codex (\texttt{gpt-6-astra}) adjudicated the same items in permuted order outside the repository, yielding more than two thousand blinded decisions (Online Resource~1, Table~S-1). Each session saw only code diffs, test-only stabilization scope, and lost mutants with production source slices. All sessions remained strictly blinded to strategy names, repair models, gate verdicts, merge status, Stage-1 labels, and peer runs, while pairing an independent U.S.-vendor ensemble with four Chinese-vendor repair models avoids same-family bias. Across all three tasks, ten-session internal stability reaches near-perfect Fleiss' $\kappa$ above 0.91, and consensus labels achieve substantial Stage-1 agreement~\cite{cohen1960kappa}. Main adjudication tables report primary arbitrated labels alongside ten-session ensemble bounds, with full $\kappa$ intervals and vote-entropy diagnostics in Table~S-1.

\subsection{Prefix-Forked Witness Experiment and Clustered Statistical Inference}

\paragraph{Prefix-Forked Witness Experiment.}
To isolate whether fault localization drives recovery beyond extra retries or longer prompts, we fork every multi-round trajectory that triggers its first erosion retry before round~5. This paired pool spans all $n = \ForkTotal$ triggers across $\ForkTests$ tests in $\ForkProjects$ repositories, and two round-5 triggers without remaining budget stay in full-cohort totals. From each identical pre-fork state, four arms completed 100\% of runs. \emph{Gate-Only} abstains immediately at 0\% recovery by definition, and \emph{Scalar Ratio} returns only $k/M$. \emph{Misleading Witness} fills the exact witness template and mutant count using already-killed mutants, whereas \emph{True Witness} supplies localized surviving mutants.

\paragraph{Project-Clustered Paired Inference.}
Because flaky tests cluster within repositories, treating tests as independent understates variance. Every paired comparison estimates test-weighted risk differences in percentage points with 95\% whole-repository cluster bootstrap confidence intervals over 20,000 resamples. We pair these estimates with equal-repository sensitivity checks and a five-point practical threshold. Paired project-level Rademacher sign-flip permutations test significance, using exact enumeration whenever at most 16 repositories show non-zero differences. Holm--Bonferroni correction controls familywise error at the 5\% level across operational soundness on all five non-mutation baselines, fixed-cohort held-out yield, and witness recovery. Section~\ref{sec:results} presents our empirical findings.
